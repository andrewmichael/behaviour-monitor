## Facts Part 2 depends on

- Chain step window default is 1800 s; stall TTL 21600 s; RouterConfig has no agreement_window_s.
- Health silent detection is gated on learning; unavailable and dropout are always on.
- Deferred minor: reset() clears holiday and snooze (Part 2 owns the switch).

## Rulings (in order)

- Ruling R1: HouseModel.expected_gap uses the 90th percentile of slot gaps, not the median — spec 6.1 says "median and spread" but bursty mornings make the median ~4 min and every quiet half hour a MEDIUM alert; p90 is "longest normal gap". Cost if wrong: welfare alerts fire later than the spec author intended (ratio thresholds bite on a larger base).
- Ruling R2: kettle_absent scenario test asserts only on kettle notes (hour 7) — random daytime windows on other entities are legitimate model output, not a defect. Cost if wrong: hides a noisy-window problem the final review should still look at.
- Ruling R3: replay exposes run_fixture_full (timeline, engine, last_poll) so promotion is asserted on the engine snapshot; router re-logs a STATISTICAL alert whose severity rises. Cost if wrong: one extra logbook line per drift severity rise.
- Ruling R4: fix the plan-mandated Severity defect — define all four comparison dunders explicitly, keep str mixin — because the router relies on `>` and `max()` over severities. Cost if wrong: none beyond four small methods; not fixing would silently break escalation and welfare_severity.
- Ruling R5: fix the plan-mandated restore gap by also triggering the restore branch on `old_unavail` — spec 5 says every unavailable-boundary transition emits a HealthEvent and restart is the named case. Cost if wrong: a possible duplicate restore HealthEvent when both signals fire; health tracker treats repeated available=True as idempotent.
- Ruling R5 amended: the implementer's stateful default (unknown entity's availability inferred from the call's old_state) supersedes my literal `or old_unavail`, which would have re-fired on every replay. Cost if wrong: none identified; re-reviewer traced all three cases.
- Ruling R6: reject the last-activity-slot anchoring — spec 6.1 says current slot, and anchoring would compare overnight silence to evening gap statistics and raise nightly false alerts. Root cause is test data: 14 training days give each weekday-hour slot two days, so Mon-10:00 has 2 gaps < MIN_GAPS_PER_SLOT. Fix: test `_train` covers 09:00-11:00. Cost if wrong: none to production code; the test becomes slightly less minimal.
- Ruling R7: HouseAssessment's last field is `last_room` (brief Interfaces line said "contributing"; code, tests and Task 12 all use last_room). Cost if wrong: a rename later.
- Ruling R8: while degraded, freeze the sustain ladder (do not call _sustain) and report severity None; on recovery the held level resumes immediately if the ratio still supports it. Spec 6.1/8 say welfare is suppressed while degraded, not erased; sensors dropping out and a real emergency can coincide. Cost if wrong: after a long degraded spell a stale HIGH could show for up to one poll before the ladder re-evaluates.
- Ruling R9: fix the test, not the code — record kettle events at 15:00 on the two "skipped" Mondays so they count as observed days and hour 8 fires on 2 of 4 Mondays. Cost if wrong: none.
- Ruling R10: replace the scalar pair count with exact per-day counts (`_Pair.days: dict[iso_day, int]`, `count` as a sum) so prune subtracts exactly the expired days; legacy `count` in stored data is ignored. Cost if wrong: a slightly larger store section per pair; no behaviour change while under the cap.
- Ruling R12: holiday suppresses welfare and statistical clear deliveries exactly as snooze does; health repair_delete still fires. Cost if wrong: a welfare alert hidden by holiday leaves no "cleared" trace in the notify channel (the persistent notification is dismissed by the coordinator on the next push cycle only).
- Ruling R13: HouseModel.expected_gap falls back to pooling the same hour across same-day-type weekdays, then across all seven, when the exact slot has fewer than MIN_GAPS_PER_SLOT gaps; still p90. Spec 6.1's 168 slots stay primary. Task 12 scope extended to house_model.py + its test for this change. Cost if wrong: early-learning expectations blur weekday/weekend differences until each slot fills; a hour that is genuinely quiet on one weekday but busy on others may under-alert on the quiet day during the first weeks.
- Ruling R14: on holiday the engine skips house evaluate and rollover (still evaluates health and submits to the router); holiday end restarts the house clock (last_activity=now, ladder reset), clears chain runs/stalls, and makes the return day the first day finalised. `_learn` pausing on holiday stands (spec 9). Cost if wrong: the first day back has no drift sample for the previous day; welfare cannot fire until the ladder re-sustains after return.
- Ruling R14 amended: holiday end restarts the house, routine and health clocks (last_event=now, no gap recorded) and clears chain runs. Cost if wrong: an entity genuinely dead across the holiday is not flagged silent until 3× its longest gap after return.
- Ruling R15: rollover walks every skipped day; drift series are recorded only for days with at least one activity event (rooms_visited non-empty) so an outage does not feed zero days; recompute/prune once after the walk. Cost if wrong: a genuine zero-activity day leaves no drift sample (the house model covers live silence anyway).
- Ruling R16: from_dict removes persisted entities absent from the configured list before set_entities. Cost if wrong: none identified.
- Ruling R17 (normaliser): only `unavailable`/`unknown` old states are restores. old_state None is a first sighting: emit HealthEvent(available=True) and run the category handler with the rising rules (motion on → PRESENCE, contact on → OPEN, panic on → PANIC, light on → LIGHT_ON, plug numeric → sample only, other → nothing). Cost if wrong: a PIR already "on" at HA start counts as one activity event; a panic button stuck on at start alerts (desirable).
- Ruling R18 (house): gaps are filed under the slot of the event that STARTS the silence, and evaluate looks up the expected gap by the slot of last_activity ("silences that begin at this hour last this long"). This supersedes R6, which rejected anchoring only because gaps were filed under the end hour; both must move together. `expected_gap(ts)` keeps its signature and means "expected silence starting at ts". Snapshot's expected_s uses last_activity. Cost if wrong: night semantics rely on the overnight gap being filed under the bedtime hour; verified by trace.
- Ruling R19 (chains): pair counts are keyed by a 3-hour time-of-day bucket of the step into A (hour // 3); significance and assembly run per bucket; chains carry the set of buckets they were learned in and dedupe by room path across buckets (pool hop stats, merge completions); a run opens only when the step into the first room falls in one of the chain's buckets. Same-room events refresh room recency so hops measure from the last event in the previous room. Cost if wrong: routines straddling a bucket boundary at ±1 h learn in two buckets (merged, fine); chains need ~min_count occurrences per bucket.
- Ruling R20 (health): a site-wide dropout latches until an evaluate has reported it once, so a transient dropout yields one `dropout` alert (repair issue) that clears at the next evaluate; the per-day counter stays. Cost if wrong: one short-lived repair issue per transient dropout.
- Ruling R21: routine_missed notes carry fired_today; router escalation counts stalls plus notes from entities alive today by distinct source; house bump needs ≥1 stall or ≥2 distinct qualifying notes; routine_agreement needs ≥2 qualifying signs. Supersedes spec 6.5's "at least one note". Cost if wrong: a single genuine missed routine no longer raises house LOW to MEDIUM; the house alert alone still escalates with time.
- Ruling R22: first numeric plug reading is judged against idle 0 (threshold = margin); reservoir seeded as before. Cost if wrong: one spurious appliance-on for a standby device at first sighting, cleared once idle is learned.
- Ruling R23: live chain run stall tolerance = max(median + 3·MAD, 3·median, 2·window_s). Cost if wrong: an abandoned routine is reported as a stall up to 30 min later than before (default window).
- Ruling R24: a stall persists until the next room step anywhere, with stall_ttl_s raised to 21600 as a safety cap. Cost if wrong: after a stall, statistical noise persists until the person moves; welfare escalation from a stale stall is bounded by 6 h.
- Ruling R25: chain step window default 1800 s (ChainConfig.window_s and EngineConfig.from_options); spec option table and Part 2 OPTION_DEFAULTS to be updated to 1800 (docs patch at end of Part 1). Deferred design note for final review: pair-learning window versus a slowing routine — a chain that slows past the window dissolves; consider scaling the window with learned hop stats.
- Ruling R26: bump Engine SCHEMA_VERSION to 2 (no v5 store has shipped) and make ChainModel.from_dict catch AttributeError alongside the existing tuple. Cost if wrong: any dev-time store is discarded on next load.
- Ruling R27: silent-sensor detection is gated on the site being learned (engine passes a no-op longest_gap while not learned); unavailable and site-wide dropout stay always-on. Cost if wrong: a sensor that dies during the learning period is only reported once learning completes.
- Ruling R28: longest gap per entity is kept per start day and pruned with the window. Ruling R29: chain steps-into counts are per bucket/room/day and pruned. Ruling R30: _last_stat persisted and replaced unconditionally each finalised day. Ruling R31: engine learning confidence uses the house model's distinct observed days.
